GuardianAI: Frailty Triage

A bilingual dashboard prototype for reviewing frailty-related signals, understanding why a case was flagged, and coordinating follow-up across a care team. It uses example records and has not been clinically validated.

View Source Code Back to Directory
“A useful risk view should help a care team find the next patient to review, understand the reason, and record what happened next.”
01 // Workflow

From a flagged case to a follow-up

Find the case: The patient registry and alert queue surface example profiles by risk level, status, and assigned clinician.

Understand the context: Profile views bring screening inputs, vital signs, trend summaries, and explanatory risk factors together so the team can review the flag.

Close the loop: Staff can acknowledge alerts, change care status, assign a provider, schedule the next review, and add notes. The same flow is available in Thai and English.

02 // Implemented Interface

What the prototype contains

Patient Registry

Search and filter example assessments and review individual profiles.

Risk Factors

Inspect the factors shown alongside a frailty-risk indicator.

Alert Queue

Acknowledge a flag and track whether it still needs review.

Care Notes

Record ownership, status, scheduling, and follow-up notes.

03 // Evidence & Boundaries

A workflow demonstration, not a clinical result

The repository contains a React/Vite client, a Node.js API, example patient data, and Thai/English localization. It demonstrates the interface and care-coordination flow.

No verified sensitivity, reduction in false alarms, advance warning window, hospital adoption, or prevented fall is established by this prototype. Those outcomes would require clinical validation and governance before any real-world use.
