Industrial IoT & OEE Data Platform

A working prototype that simulates machine readings, streams dashboard updates through WebSockets, stores data in PostgreSQL, and builds hourly Overall Equipment Effectiveness (OEE) summaries.

View Source Code Back to Directory
“Machine data helps only when operators can see what changed, understand the production impact, and decide what to inspect next.”
01 // Problem & Approach

From sensor readings to an operator view

Machine vibration, temperature, current, and cycle-time readings are difficult to interpret as isolated rows. This prototype brings them together in a live monitor so an operator can inspect machine state and possible anomalies in context.

A simulator supplies the demo readings. A FastAPI service receives and stores them in PostgreSQL, broadcasts updates to the React dashboard via WebSockets, and exposes API endpoints for machine health and OEE.

02 // Production Efficiency

What the OEE view explains

The hourly data mart combines three familiar production measures. The cards describe the calculation rather than claiming a factory performance result.

Availability

How much planned production time the machine was running.

Performance

How actual cycle speed compares with the expected pace.

Quality

How many produced parts meet the intended quality criteria.

OEE

Availability × Performance × Quality, shown alongside machine-health signals.

03 // Implemented System

A testable end-to-end pipeline

Live path: Python sensor simulator → FastAPI ingestion → PostgreSQL storage → WebSocket updates → React operations dashboard.

Analysis path: Batch processing creates hourly OEE summaries; model components support anomaly and quality investigation with machine-health and feature-impact views.

Scope: The repository demonstrates these flows with simulated telemetry. It does not establish production PLC integration, a verified 12,000-event-per-second throughput, or measured downtime reduction at a factory.
